# 赔款发展三角 · 月结网页

精算月结工具：Flask + SQLite。按月导入赔款 CSV、逐月封账、按（事故月 × 支付月）
净变动归档汇总，并可按任一己结月回查当时的累计赔付发展三角。

## 快速开始（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在名为 `closing-data` 的卷中（容器内 `/data/closing.db`）。
删除数据重来：`docker compose down -v`。

## 网页演示流程（补报 + 两期回查）

仓库自带两批演示数据：`demo/claims_2026-01_base.csv`（基础批）、
`demo/claims_2026-02_supplement.csv`（补报 + 更正批）。

1. **设置首个待结月**：首页 →「待结月设置」→ 填 `2026-01`。
2. **导入基础批**：「导入赔款」→ 选择 `claims_2026-01_base.csv` → 导入
   （7 笔，计入 2026-01 期）。
3. **封账 2026-01**：「封账」页可预览本期净变动组合 → 确认封账，待结月推进到 2026-02。
4. **导入补报/更正批**：导入 `claims_2026-02_supplement.csv`（7 笔，其中 3 笔同号覆盖：
   C-0002 改金额 80000→95000；C-0004 改支付月 2026-01→2026-02；C-0007 同数重报）。
5. **封账 2026-02**：本期只归档 6 个净变动组合（C-0007 无净变动，不产生归档行）。
6. **两期回查**：「三角回查」起始事故月选 `2025-10`：
   - 已结月选 `2026-01`：仍是当时口径（如 2025-10 事故月 2025-12 累计 200,000），
     2026-02 列留空（封账月之后留空）；
   - 已结月选 `2026-02`：含补报更正（同格变为 215,000），新增 2026-02 事故行。
   - 「归档明细」可查看每期净变动组合（只读汇总）。

也可以脚本化演示（服务已启动时）：

```bash
bash scripts/demo_curl.sh http://127.0.0.1:8000
```

## CSV 格式

表头四列（顺序不限，支持 `赔款号/事故月/支付月/金额` 等别名）：

```csv
claim_no,accident_month,payment_month,amount_cents
C-0001,2025-10,2025-10,120000
```

- `claim_no`：赔款号，每批内唯一；与历史批次同号则**整笔覆盖**（可改事故月、支付月、金额）。
- `accident_month` / `payment_month`：`YYYY-MM`；支付月须在事故月至当前待结月之间（含首尾）。
- `amount_cents`：非负整数，单位分，单笔最多 15 位（≤ 999,999,999,999,999）。
- 任一行非法 → 整批拒绝，不留部分结果。

## 大额合计（超出有符号 64 位）

单笔仍限 15 位，但**批次合计、首页总额、归档净额、三角累计不受 int64 限制**：
金额列以十进制文本存入 SQLite，所有加减与合计在 Python 任意精度整数上完成，
即使一期合计超过 9,223,372,036,854,775,807 分也精确到分。

例如 9,225 笔各 999,999,999,999,999 分（单笔均合法，合计 ≈ 9.22e18 > int64）：

```bash
python3 scripts/make_big_csv.py /tmp/big.csv
# 网页导入该文件，首页/封账预览/归档明细/三角累计都会显示完整 22 位合计
```

已有旧库（金额列为 INTEGER）无需重建：启动时自动把这些列重建为 TEXT，
历史数据原样保留，可继续导入封账。

## 设计要点

- **期间归属**：每批记录导入时的待结月为所属期间；封账时只归档本期批次的净变动。
  导入与封账重叠时，进程内写锁 + SQLite `BEGIN IMMEDIATE` 单事务保证整批按提交
  先后计入本期或下期，失败整体回滚。
- **任意精度金额**：`app/money.py` 统一负责单笔 15 位校验、文本↔整数转换与格式化；
  库内金额列一律为规范十进制 TEXT，读写都在 Python 整数上完成，避免 `SUM()`
  或 int64 参数绑定溢出。三角与归档合计按组合在 Python 中累加，正负抵消后精确为 0。
- **增量归档**：`claim_archived` 保存每笔赔案最近封账时的快照；封账时对本期触及的
  赔案做「当前值 − 归档快照」差分，只为净变动非零的（事故月 × 支付月）组合写
  `archive` 行，随后推进快照与待结月。补报和更正因此从下一次封账起可见。
- **只读回查**：三角回查只读 `archive` 汇总（`close_month ≤ 所选已结月` 求和后逐月
  累计），已结三角不受后续补报/更正影响。列范围到最新已结月，封账月之后留空，
  事故月之前显示「—」，已到月份零额显示 0。查询按 `(事故月, 支付月)` 聚合到内存
  字典，内存随涉及的组合数增长，而不随单个组合的归档行数增长。
- **封账约束**：只能封当前待结月，成功后自动进入次月；有数据后首个待结月不可再改。
- **单次提交**：导入整批一次提交、封账（归档 + 快照 + 待结月推进）一次提交；
  任一步失败整体回滚，保留操作前的数据与待结月。

## 目录结构

```
app/            Flask 应用（months/db/logic/views + templates/static）
run.py          启动入口（0.0.0.0:8000）
demo/           演示用两批 CSV
scripts/make_big_csv.py  生成合计超出 int64 的演示 CSV
tests/selftest.py  关键操作自测
scripts/demo_curl.sh  命令行演示脚本
Dockerfile / docker-compose.yml
```

## 已知限制

- 使用 Flask 内置服务器（单进程多线程），面向内部演示/小团队；生产化可换
  gunicorn（须保持单 worker 以维持进程内写锁，或改用数据库级互斥）。
- 无登录鉴权；单笔金额上限 15 位整数分（合计不受此限）；时间戳为 UTC。
